# Controlled topics and risk performance (v4)

Apply `2026_10_02_000003_add_learning_topic_to_tasks_table.php` before deploying the updated controllers/exporters. It adds an indexed, nullable foreign key to `learning_topics.id` with ON DELETE SET NULL. It performs no backfill or updates to existing rows. Quizzes keep their existing topic column and relationship.

Professors select an existing learning topic in quiz create/edit forms or the classroom task editor. The empty choice leaves/removes the standardized assignment. Quizzes with attempts expose a separate topic-only PATCH form; questions and historical scores stay locked. That action never invokes recommendation generation. Attempt submission and simulator experiment behavior remain unchanged. Topic names are managed through the existing administrator learning-topic catalog, not inferred from titles or descriptions.

`additional_features.topic_quiz_performance` and `topic_task_performance` are maps keyed by topic ID. Each entry contains `topic_name`, `average`, and respectively `attempt_count` or `graded_task_count`. Quiz counts refer to latest valid real attempts per quiz, not all retries. Task counts refer to usable graded tasks after selecting latest eligible submissions. Both reuse existing class/cutoff and grading rules. Untagged or unscored content is excluded. Attendance and current academic grade calculations are unchanged. No weak-topic threshold, labels or training are added.

CSV fixed numeric columns remain in place, including the deliberately empty `topic_task_average` scalar. Dynamic quiz topic columns are replaced by `topic_quiz_performance_json` and `topic_task_performance_json`, with `{}` when no scored topics exist. Consumers should parse these columns as structured JSON; they are not numeric predictors. v4 prevents reuse of cached v3 snapshots lacking this structure.

Four class content counts (`tagged_quiz_count`, `untagged_quiz_count`, `tagged_task_count`, `untagged_task_count`) describe records created by cutoff, including tasks not yet due; they are metadata, not student predictors. They repeat on each student row. Readiness reporting counts this inventory once per class and reports both unique students and unique student-class pairs with at least one topic score. Its additional `*-topics.csv` contains aggregates only. Contradictory class counts and malformed topic JSON are rejected without echoing sensitive data. Archived dynamic-topic CSVs remain readable; unavailable archived inventories are not invented as zero.

Topic assignments and names are current metadata. The schema does not retain assignment history, so changing a topic later cannot reconstruct which tag was known at an older cutoff. Preserve exported CSVs/snapshots as immutable artifacts; use current cutoffs for newly tagged content. If historical as-of topic membership becomes a research requirement, implement effective-dated topic-assignment history before claiming that guarantee. Counts and score availability do not establish ML usefulness or accuracy.
