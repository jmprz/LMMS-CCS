# Research snapshots (frozen v5)

Create a current, unlabeled package:

```sh
php artisan risk:research-snapshot --name="baseline-v5"
php artisan risk:research-snapshot --name="week-1" --classes=1,2,3
```

The command captures the current application-timezone timestamp once, rounded to seconds. All feature rows, collection reports, label-readiness inspection and metadata use that point. By default, selection follows the existing exporter: active classes with student enrollment by cutoff. Explicit class IDs follow its existing explicit-selection behavior. Students in multiple classes retain one pseudonymous grouping key and one row per class; split future training data by that grouping key.

Files are written under `storage/app/risk-datasets/research-snapshots/{sanitized-name}-{YYYYMMDD-HHmmss}/`:

- `ml-ready.csv`: existing v5 ML-ready schema, no raw student identities, outcomes or target labels; missing values remain empty.
- `collection-status.csv` and `collection-status.json`: existing aggregate collection reports, restricted to the same scope and cutoff.
- `label-readiness.txt`: aggregate joins, duplicate/timing checks, outcome counts and passing-criterion status. Target distributions are deliberately not calculated, even when a criterion exists. Outcome revisions must have been recorded/created by cutoff; the latest eligible imported revision is selected. Missing recording timestamps remain identifiable in readiness inspection and are excluded from valid-timestamp collection coverage.
- `metadata.json`: scope, counts, timezone/cutoff, version, criterion status, optional Git commit, worktree dirty flag, predictor-scope hash, current research-code hash and SHA-256 checksums for the other four files. The code hash covers risk services/commands, the snapshot service/command, outcome reader and risk config files; it is not a full application build hash. Secrets and source text are never exported.

Default operation reads database records without modifying them. One outer transaction retains a consistent database view (explicit repeatable-read isolation on production MySQL). Existing nested report/export transactions remain inside that outer transaction.

Only explicitly adding `--save-features` allows the existing exporter to save/reuse student feature snapshots. All such writes roll back if any artifact fails. No other collection/outcome data is written. Labels and models are never generated by this command, regardless of outcomes or configuration.

Names become safe slugs (maximum 80 characters); paths, traversal and control characters are rejected. Directory creation and artifact creation are exclusive. An exact directory collision fails before export or feature persistence, preserving the previous package. On failure, only this invocation's newly created files are removed. Metadata is written last as the completion marker.

Immutability here means the command never overwrites an existing package. It does not install filesystem ACLs or prevent a person from editing/deleting files manually. Verify artifact checksums before reuse and archive completed packages with your research records. A cutoff alone cannot reconstruct previously overwritten live records; retain the CSVs and metadata. The current code hash and dirty flag supplement Git commit identification when local changes have not been committed. Pseudonymous grouping keys are linkable research identifiers; protect these files as research data.

No feature formulas, predictor semantics, grade/outcome rules or passing thresholds are changed. Existing standalone risk commands retain their defaults.
